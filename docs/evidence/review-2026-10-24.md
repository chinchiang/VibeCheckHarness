# 設計審查紀錄（2026-10-24）

> **這份紀錄的用途**：保存 2026-10-24 對 v0.3 設計的審查結論，讓 v0.4 的每一項修正都能追溯到審查發現與 v0.3 的證據位置；也列出本輪**沒有**處理的項目與理由。
>
> - **審查對象**：v0.3（commit `3fcfee4`）。docs/00–09、`docs/schemas/`、`docs/examples/`、`tools/vchlib/`。
> - **方式**：三個唯讀代理分頭逐行讀完（02＋05／03＋08＋程式碼／04＋06＋07＋01），再由主審查者對照原文或程式碼核對最嚴重的主張。標 **[核實]** 者已直接對照原文或程式碼確認。
> - **行號**：v0.3 的 `檔案:行號`。
> - **處理原則**（依使用者決定）：先處理「第一優先」中的裁決規則與 validator（§2、§3）；寫入範圍的其餘項目、法務順序、信任錨、路線圖留待下一輪（§5）。

## 1. 總評

- **方向合理**：遮罩先於任何 LLM、工具輸出不給審查者、確定性裁決、簽章關卡、寫入綁種子、預先登記的校準假設與後備方案，都是正確且少見的設計選擇。
- **會讓「結果可信」落空的三類問題**：裁決規則的邊界錯誤（§2）、validator 的「通過」可被偽造（§3）、跨境法務聲明排在程式碼出境之後（§5 C1）。前兩類在 v0.4 處理。

## 4. 本輪的語意決定（可回退）

- **R10 讓位給 `E_proof`**：v0.3 的設計是「G2 駁回為最終決定」。v0.4 改為只對投票、SARIF 與 `E_fail_u` 是最終；可執行證明會覆蓋它。理由：事先登記、重播成立的確定性 FAIL 比測試出現前的人工判斷更有力，而 `REJECTED` 會讓 SARIF 在 IDE／CI 中被壓掉。若要回到 v0.3 的語意，只需移除 `adjudicate._decide` 中 R10 分支的 `E_proof` 例外。
- **G2 accept 仍不是規則輸入**：讓人工 accept 改變狀態，需要先決定它能升到哪個狀態、是否受 R8 限制；留待下一輪。
- **片段門檻 12 個非空白字元**是設計假設 [H]，範例中最短的片段有 35 個字元。

## 5. 本輪沒有處理的項目

下列項目在審查中提出，本輪刻意不處理，留待下一輪（下一輪的優先順序以使用者決定為準）：

**第一優先中的寫入範圍（其餘部分）**
- 有副作用的 GET、`X-HTTP-Method-Override`／`_method`；白名單不約束 query、body、header；W0 已知 handler 是否寫入 DB 卻未用於安全等級（04:400、173、682）。
- webhook 與 LLM agent 端點被列為 create-only，但下游副作用在請求層看不到（04:258；seed-manifest.yaml:28-29）。
- Schemathesis 多列標 S1，但會自行產生 ID 與 body（04:250、263、273、280）。
- Next.js Server Actions 與 PostgREST 的寫入在現行規則下一律 S3（09 BL-24／25 的延伸）。
- seed manifest 只有路徑由 ROE 簽署，內容 hash 在 G4 才綁（03:1015）。

**其他 validator 項目**
- 嚴重度路由（G2 佇列、W4 輸入）採信 LLM 自報的 severity（05:124、02:448、08:1933）。
- 合格票只檢查引用的證據存在，不檢查與立場相關（05:190-191）。
- `provisional` 對 R1／R7 黑箱叢集的語意（05:252-256）。
- 權重 w＝2a−1 混合真陽性與真陰性率（05:355-360）。
- `anonymized`／`order_randomized` 自填、G4「最新紀錄」以自填時間排序、`actor.kind: system` 不需簽章、`run_resume` 不驗角色（`derive.py:91-94、352-354`；`checks.py:487-494`）。
- 無簽章的 EXPIRED 可跳過 G2（08:341）；`idempotency_key` 可為 null（範例 49/60 筆）。

**法務、信任錨與架構**
- C1 **[核實]**：`cross_border` 只在 ROE（G0b 檢查），委任設定沒有任何跨境或法務欄位，但 W2 在 G0b 之前就把 C 級程式碼送往雲端模型（roe.yaml:177、engagement.yaml:71-73、06:274）。
- `tools.yaml`／`models.yaml` 不簽章；Z3 執行 LLM 產生的腳本卻沒有隔離規格；job 帳本在 checkpoint 內，時間旅行重播會倒退；所有時效檢查都用自填時間；HMAC 金鑰區位矛盾；LLM 快取鍵不含委任與資料等級。
- Scope Proxy：IPv6 分類（NAT64 等）、h2c／QUIC、`%5C`、共享平台網域清單缺 `lovable.app`、`replit.app` 等。

**路線圖與產品定位**
- F1 **[核實]**：「多家族勝過單一模型多次取樣」明文不作為出口條件（07:36、192），校準在 MVP-3 之後；MVP-0～2 期間多家族機制實際不起作用。
- MVP-0 的出場條件不含法務閘門結案（07:67）；出口準則多在自建應用上以錄製回應量測。
- Lite 單人模式的門檻與人力需求；G2／G3 佇列沒有上限與剪枝。

**威脅類別與範例**
- Next.js middleware 繞過、Server Actions 授權、Supabase RLS 只測 SELECT、MCP 工具描述投毒、受測應用的 CI／CD 與 IaC 等未涵蓋。
- 對照表：open redirect 對到 `WSTG-v42-CLNT-04`（DOM 型）；CSRF 用 `playwright:api` 驗不了 SameSite；範例 B 標「間接」注入但注入者是使用者本人；`zap-api-scan.py` 列為 S0 的被動模式（待以 E:blackbox-07 原文確認預設行為）。
- 範例與 JSON：`testcase.idor` 的計數 oracle 偵測不到 PUT 修改；範例 B 的 `Q-refund-calls` 只查 u2_order；n′ 沒有欄位；K-015 併入 T-012 後沒有黑箱裁決。
